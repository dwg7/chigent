# genkan 仕様(草案 0.1)

genkan(玄関)は、chigent のエージェントが返す**短いリンクの契約**と、そのリンクを受けて地理院地図を開く**中継ページ**です。試作(2026-10)で、安定の約束はまだありません。

- 実体: `https://dwg7.unopengis.org/chigent/genkan/`(`docs/genkan/`)
- 実装: `src/genkan.ts`(ブラウザ用の JS は `scripts/build-genkan.ts` が生成)
- 対応するプロンプト: `prompt/genkan.md`

## 1. 考え方

1. エージェントが出すのは「地図の意図」(位置・背景・重ねる図)だけ。画面の状態(`blend` `disp` `lcd` `vs` `d`)は、受け手が決まった値で入れる(DECISIONS D-002)。blend の桁数、`/&` の脱落、`%7C`、緯度経度の取り違えといった、これまでの誤りの多くが、構造的に起きなくなる。
2. 仕様は最小にし、残りは**あえて未定義**にする。送り手(エージェント)は定義された部分だけを出す。受け手(ページ)は、それ以外を寛容に扱ってよい。送り手の適合は機械で測れる(`src/grade.ts`)。
3. 地理院地図は、画面の全状態を URL のフラグメントに持つ。genkan も同じ流儀で、全部をフラグメントに置く。地理院の URL とほぼ同じ形で、慣れた書き方がそのまま使える。

## 2. リンクの形

```
https://dwg7.unopengis.org/chigent/genkan/#14/36.228823/137.586174/&b=std&l=vlcd_yakedake
```

RFC 5234 の ABNF で書く。

```
genkan-ref = origin "#" view [ "/&" params ]
origin     = "https://dwg7.unopengis.org/chigent/genkan/"
view       = zoom "/" lat "/" lon
zoom       = 1*2DIGIT                          ; 0..18
lat        = [ "-" ] 1*DIGIT [ "." 1*DIGIT ]   ; 小数 6 桁まで
lon        = [ "-" ] 1*DIGIT [ "." 1*DIGIT ]   ; 小数 6 桁まで
params     = param *( "&" param )
param      = "b=" id                           ; 背景。省略は std
           / "l=" id *( "," id )               ; 重ねる図。下から上の順。省略は無し
           / "m=" ( "p" / "g" / "n" )          ; 表示の仕方(任意)
id         = 1*( ALPHA / DIGIT / "_" / "-" / "." )
```

| 部分 | 意味 |
|---|---|
| `z/lat/lon` | ズーム(整数)、緯度、経度(十進度)。**必須。** 位置引数で、地理院の `#z/lat/lon` と同じ順 |
| `b` | 背景地図。`std` `pale` `blank` `english` `ort`(`ort` は「写真」。地理院の `layers0.txt` で、タイルは `seamlessphoto` と同じ)。省略は `std` |
| `l` | 背景の上に重ねる図の ID を `,` で区切る。下から上の順(地理院の `ls` と同じ向き)。**背景は含めない** |
| `m` | 表示の仕方。`p` ページ + フレーム(既定)、`g` 確認なしで転送、`n` ページのみ(フレームなし)。受け手の裁量が大きい |

- ID は `layers.txt` の綴りのまま(大文字小文字を区別する)。
- 1 文字の名前は、この仕様のために予約する。2 文字以上は、拡張に使ってよい。
- 未知のパラメーターは無視される。バージョンの番号は持たない(互換が壊れるときに追加する)。

## 3. 受け手の動作

C 言語の語彙を借りて、分けておく。

**規定(受け手が守る)**
- `#` 以降の `z/lat/lon` を読み、位置が欠けている・数値でない・範囲外のときは、**何も開かず**、読めなかったと表示する(黙って別の場所を開かない)。
- 開く先は、必ず `https://maps.gsi.go.jp/#…` だけ。入力から作る文字列は、すべてエンコードして `ls` の中に閉じ込める(別のパラメーターを足せない)。
- 地理院の URL には、`base`(= `b`)、`ls`(= 背景 + `l`)、`blend`(0 を n−1 個。n=1 なら書かない)、`disp`(1 を n 個)、`lcd`(最後の図の ID)、`vs=c1g1j0h0k0l0u0t0z0r0s0m0f1`、`d=m` を入れる。
- 要約(「標準地図 + 焼岳、ズーム14、北緯… 東経…」)を表示し、利用者が AI の判断を目で確かめられるようにする。

**処理系定義(受け手ごとに決めてよい。文書化する)**
- 位置の直後の区切りの寛容さ(この実装は `/&` `&` `?` `/?` を受け付ける)。
- ID の大文字小文字の補正(この実装は図の表で正しい綴りにする)。
- 緯度と経度の入れ替えの検出(この実装は、緯度に収まらず経度の側が緯度として収まるときだけ入れ替え、警告する)。
- `b` に背景でない ID が来たときの扱い(この実装は、`b=seamlessphoto` を `b=ort` に読み替え、それ以外は重ねる図として扱う)。
- `l` に背景の ID が来たときの扱い(この実装は除く)。
- 地理院の名前(`base`、先頭が背景の `ls`)の受け付け。
- ズームの範囲外、図のズーム範囲外のときの注記。
- 重ねる図の数の上限(この実装は 8)。

**未規定(複数の結果のどれでもよい)**
- 同じパラメーターの重複(`b` は最後を採る。`l` は順に連結する、が、この実装の挙動)。
- 非 ASCII の ID(パーセントエンコードが要る)。

**未定義(送り手が出してはならない形)**
- 表にない ID、`b` の未知の値、空の要素(`l=a,,b`)、仕様にない値の `m`。受け手は何をしてもよい。

## 4. URL としての正しさ

- クエリ(`?`)ではなくフラグメント(`#`)に置く。RFC 3986 §3.5 は、フラグメントを「第一の資源に対する第二の資源(その一部、または**ある見方**)の間接的な指定」と定め、参照を解くときに URI から切り離され、サーバーには送られないとする。地図の位置と図は、地図という資源に対する見方である。地理院・OSM・Leaflet・MapLibre と同じ流儀でもある。
- 文字は RFC 3986 のフラグメント(`pchar / "/" / "?"`)に収まり、WHATWG URL Standard のフラグメントのパーセントエンコード集合にも含まれない。`l` の区切りの `,` は `sub-delims` で、生のまま使える。地理院の `ls` の区切り `|` は `sub-delims` にもなく、`%7C` と書かねばならない。genkan はその問題を持たない。
- `&` 以降は `application/x-www-form-urlencoded`(WHATWG URL Standard §5.1)として読む(`URLSearchParams`)。`+` は空白になるので、ID に `+` を含められない(今日の ID には無い)。
- 機械で確かめる性質: 送り手が書くリンクは、WHATWG の `new URL(s).href === s`(直列化しても変わらない)を満たす(`tests/genkan.test.ts`)。

## 5. 実装と検証

- `src/genkan.ts`: `parseGenkan`、`genkanToGsiUrl`、`buildGenkanUrl`、`summarize`、`toGsiIntent`、`fromGsiIntent`。
- `docs/genkan/`: `index.html`(CSP で自分自身と地理院のフレームだけを許す)、`page.js`(DOM の組み立てだけ。`innerHTML` は使わない)、生成された `genkan.js` `gsi-url.js` `mapintent.js`、図の表 `layers.json`。
- 採点: `scripts/collect-answers.ts --genkan` が、エージェントの回答のリンクを地理院の URL に直して、従来の採点(`src/grade.ts`)にかける。
- テスト: `tests/genkan.test.ts`(契約と変換)、`tests/genkan-build.test.ts`(生成物の一致、ページの安全性)。

## 6. 未決

- 表示の既定(ページ + フレームで始めたが、転送・ページのみとどれが好まれるかは、実機で測る)。
- フラグメントの生存率(チャットの描画や安全対策で、`#` 以降が落ちないか。Copilot と源内で測る)。落ちたときは、位置が無いので、何も開かない(上の規定)。
- 地理院の URL の `ls` を契約に取り込むか(いまは入力として読むだけ)。
- 不透明度・非表示・乗算(`blend=1`)・2 画面表示は、契約にまだ無い。実例では 1〜5%(2 画面は約 3%)。
- 地理院側が、埋め込み時に親へ状態を通知する仕組み(`postMessage` など)を持つと、外側の URL を現在の状態に同期できる。ソースを確認した限り(a5ad2a4)、いまは無い。
